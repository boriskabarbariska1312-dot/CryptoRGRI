Шифрование большого текста (размер полного текста «Войны и мира» в формате .txt составляет около 3–4 МБ) — это идеальный сценарий для проверки вашей утилиты cryptum. Такой объем данных заставит программу выполнить десятки итераций чтения и записи через ваши 64 КБ буферы и наглядно покажет, насколько стабильно работает логика чанковой обработки и финализации блоков (особенно для алгоритмов с паддингом вроде Blowfish или MTProto).
Ниже приведено пошаговое руководство, как скачать книгу и зашифровать её разными способами прямо в консоли.
Шаг 1. Подготовка файла книги
Если файла еще нет в вашей рабочей директории build, скачайте текстовую версию романа (например, одним файлом) через терминал:
curl -L "https://raw.githubusercontent.com/mamant/text-processing/master/data/voyna-i-mir.txt" -o war_and_peace.txt

Размер скачанного файла составит около 3.2 МБ.
Шаг 2. Выбор сценария шифрования
Вы можете использовать любой из поддерживаемых вашей утилитой алгоритмов. Вот 3 основных варианта:
Вариант А: Шифр Атбаш (Тест потоковой инверсии)
Самый быстрый способ, не требующий создания ключей. Файл обрабатывается байт за байтом.
• Шифрование: ./cryptum -a atbash -m encrypt -i war_and_peace.txt -o war_and_peace_atbash.enc
• Дешифрование: ./cryptum -a atbash -m decrypt -i war_and_peace_atbash.enc -o war_and_peace_atbash_dec.txt
Вариант Б: Шифр Гронсфельда (Исторический тест)
Используем тематический цифровой ключ — например, 1812 (год начала Отечественной войны).
• Создание ключа: echo -n "1812" > war1812.key
• Шифрование: ./cryptum -a gronsfeld -m encrypt -i war_and_peace.txt -k war1812.key -o war_and_peace_gron.enc
• Дешифрование: ./cryptum -a gronsfeld -m decrypt -i war_and_peace_gron.enc -k war1812.key -o war_and_peace_gron_dec.txt
Вариант В: Стойкое блочное шифрование (Blowfish или MTProto)
Самый надежный вариант, требующий генерации полноценного бинарного ключа. Здесь утилита проверит корректность работы с вектором инициализации (IV) и выравниванием хвоста файла по PKCS#7.
• Генерация криптостойкого ключа: ./cryptum -a blowfish -m generate-key -s secret_bf.key
• Шифрование: ./cryptum -a blowfish -m encrypt -i war_and_peace.txt -k secret_bf.key -o war_and_peace_bf.enc
• Дешифрование: ./cryptum -a blowfish -m decrypt -i war_and_peace_bf.enc -k secret_bf.key -o war_and_peace_bf_dec.txt
Шаг 3. Верификация результатов (Проверка на искажения)
Поскольку текст большой, проверять его глазами неэффективно. Чтобы убедиться, что архитектура распределения памяти и логика плагинов отработали без потери или добавления лишних байт на стыках 64-килобайтных блоков, используйте системные утилиты проверки целостности.
Способ 1: Побайтовое сравнение утилитой diff
Команда не должна выводить ничего. Если терминал просто перешел на новую строку — файлы абсолютно идентичны:
diff war_and_peace.txt war_and_peace_bf_dec.txt

Способ 2: Сравнение SHA-256 хэшей файлов
Сгенерируйте хэш-суммы для оригинального файла и для расшифрованного. Они должны совпадать до последнего символа:
shasum -a 256 war_and_peace.txt
shasum -a 256 war_and_peace_bf_dec.txt

Дополнительный тест: Сжатие «на лету» через конвейер
Вы можете зашифровать книгу и сразу перенаправить вывод в системный архиватор, чтобы сохранить зашифрованный сжатый архив:
./cryptum -a atbash -m encrypt -i war_and_peace.txt -o - | gzip > war_and_peace.enc.gz





Полный перечень консольных тестов для алгоритмов Атбаш (Atbash) и Гронсфельд (Gronsfeld). Эти тесты покрывают как стандартные сценарии, так и проверку потоков ввода-вывода (stdin/stdout) и обработку специфических ошибок.
Подготовительный этап (Создание тестовых файлов)
Перед запуском тестов выполните в терминале команды для создания исходного текста и различных типов ключей:
# Создание основного текстового файла
echo "Hello, World! Cryptum testing 2026." > input.txt

# Создание пустого файла для проверки граничных условий
touch empty.txt

# Создание тестовых ключей для Гронсфельда
echo -n "1234" > key_numeric.txt
echo -n "abcd" > key_alpha.txt
echo -n "5" > key_short.txt

Блок 1: Тестирование алгоритма Атбаш (Atbash)
Особенность: не требует передачи ключа (key_size == 0), выполняет инверсию каждого байта (255 - byte).
Тест 1.1: Классическое шифрование и расшифрование через файлы
• Команды: ./cryptum -a atbash -m encrypt -i input.txt -o atbash_enc.bin ./cryptum -a atbash -m decrypt -i atbash_enc.bin -o atbash_dec.txt cat atbash_dec.txt
• Ожидаемый результат: В консоли должен напечататься исходный текст: Hello, World! Cryptum testing 2026.. Файл atbash_enc.bin заполнен нечитаемыми бинарными символами.
Тест 1.2: Работа с конвейерами (Pipes) и стандартными потоками stdin/stdout
• Команда: cat input.txt | ./cryptum -a atbash -m encrypt -i - -o - | ./cryptum -a atbash -m decrypt -i - -o -
• Ожидаемый результат: Данные передаются через оператор -, шифруются и расшифровываются «на лету» в памяти. В консоль мгновенно выводится исходная строка.
Тест 1.3: Обработка пустого файла
• Команды: ./cryptum -a atbash -m encrypt -i empty.txt -o empty_atbash.bin ls -l empty_atbash.bin
• Ожидаемый результат: Команда завершается успешно (код 0). Размер созданного файла empty_atbash.bin строго равен 0 байт.
Блок 2: Тестирование алгоритма Гронсфельд (Gronsfeld)
Особенность: выполняет многоалфавитный сдвиг. Длина ключа динамическая.
Тест 2.1: Шифрование со стандартным цифровым ключом
• Команды: ./cryptum -a gronsfeld -m encrypt -i input.txt -k key_numeric.txt -o gron_enc1.bin ./cryptum -a gronsfeld -m decrypt -i gron_enc1.bin -k key_numeric.txt -o gron_dec1.txt cat gron_dec1.txt
• Ожидаемый результат: Текст успешно зашифрован со сдвигами на 1, 2, 3, 4 и полностью восстановлен без искажений.
Тест 2.2: Использование буквенного ключа (Устойчивость плагина)
Логика плагина автоматически приводит буквенные символы к цифрам по формуле символ % 10.
• Команды: ./cryptum -a gronsfeld -m encrypt -i input.txt -k key_alpha.txt -o gron_enc2.bin ./cryptum -a gronsfeld -m decrypt -i gron_enc2.bin -k key_alpha.txt -o gron_dec2.txt cat gron_dec2.txt
• Ожидаемый результат: Программа не падает. Сдвиг успешно рассчитывается на основе ASCII-кодов букв a, b, c, d. Текст расшифровывается корректно.
Тест 2.3: Минимальный размер ключа (Ключ из одного символа)
• Команды: ./cryptum -a gronsfeld -m encrypt -i input.txt -k key_short.txt -o gron_short.bin ./cryptum -a gronsfeld -m decrypt -i gron_short.bin -k key_short.txt -o gron_short_dec.txt cat gron_short_dec.txt
• Ожидаемый результат: Алгоритм циклически применяет сдвиг 5 к каждому байту сообщения. Файл успешно расшифрован.
Тест 2.4: Обработка пустого файла с ключом
• Команды: ./cryptum -a gronsfeld -m encrypt -i empty.txt -k key_numeric.txt -o empty_gron.bin ls -l empty_gron.bin
• Ожидаемый результат: Утилита отрабатывает штатно, создавая пустой файл empty_gron.bin размером 0 байт.
Блок 3: Нештатные ситуации и обработка ошибок
Тест 3.1: Запуск Гронсфельда без флага ключа (Ошибка динамической библиотеки)
Поскольку в AlgorithmInfo для Гронсфельда указан нулевой размер ключа (из-за его динамической длины), парсер CLI пропускает выполнение функции. Ошибку перехватывает сама библиотека на этапе проверки входящего буфера.
• Команда: ./cryptum -a gronsfeld -m encrypt -i input.txt -o gron_error.bin
• Ожидаемый результат: Программа корректно прерывает операцию и выводит системное сообщение: Ошибка в динамической библиотеке при обработке данных
Тест 3.2: Защита от взаимной блокировки (Deadlock) на stdin
Проверяет логику запрета одновременного перенаправления входных данных и ключа в один поток терминала.
• Команда: ./cryptum -a gronsfeld -m encrypt -i - -k -
• Ожидаемый результат: Программа мгновенно останавливает работу, не уходя в бесконечное ожидание. Выводится справочная информация (Help) с интерфейсом CLI.




echo -n "2026" > key.txt


./cryptum -a gronsfeld -m encrypt -i input.txt -k key.txt -o input_gron.enc


./cryptum -a gronsfeld -m decrypt -i input_gron.enc -k key.txt -o input_gron_dec.txt
