Документация `README.md` составлена строго по требованиям вашего Технического задания (ТЗ) и сохранена в корень проекта.

### Какие разделы ТЗ были строго учтены в этой документации:
1. **Область применения и наименование:** Зафиксировано название `Multi-Algo Cryptotool` (`cryptum`) и его учебное/демонстрационное назначение для обработки любых бинарных форматов файлов.
2. **Спецификация бинарного интерфейса (C ABI):** Описано использование экспортируемых функций `encrypt`, `decrypt`, `get_algorithm_info`, `get_output_size`, а также низкоуровневых оберток над сырыми байтами `ConstBuffer` и `MutBuffer`.
3. **Требования к организации данных и надежности:** * Отображен полный запрет на использование текстовых строк (`std::string`) для хранения ключей и шифротекстов — данные переносятся строго через массивы байт (`std::vector<uint8_t>`).
   * Документировано безопасное зануление памяти перед её освобождением (`Secure Erase`) без вырезания оптимизациями компилятора.
   * Описан сквозной механизм выравнивания блоков по стандарту **PKCS#7**.
4. **Режимы функционирования и логический контроль:** Четко разграничены 3 взаимоисключающих режима: справочный, генерации ключа, криптографического преобразования. Отражена защита ядра от потенциального зависания терминала (`Deadlock`) при одновременной перегрузке `stdin` для ключа и данных.
5. **Системные показатели и стандарты сборки:** Зафиксированы требования к ОЗУ (потребление до 128 Мб при стриминге файлов размером до 1 Гб). Прописана сборка на базе **C++17** и систем сборки CMake/Make.
6. **Развертывание и инсталляция:** Добавлена информация об автоматических скриптах инсталляции и деинсталляции для Linux (`.sh`) и Windows (`.bat`), обновляющих системные пути переменной `$PATH`.
7. **Тестирование:** Включено описание тестового модуля, жесткого детерминированного задания IV для тестов и выполнения требования побайтовой идентичности массивов.
